vga_sync
- vga monitor has no memory of picture, it draws a pixel at a time (left to right, top to bottom)
- we have to tell it where each line & frame starts
	- Hsync: short pulse that means "start a new line"
	- Vsync: short pulse that means "start a new line"
- our job is to count, while one counter tracks hc (column) & one tracks vc (row)
- when hc reach the end of the line, it resets to 0 and vc goes up by 1. when vc reaches end it resets too.

- screen is 640x480, but each line is 800 clock cycles long and each frame is 525 lines. extra time is blanking (leftover from CRT monitors), is needed to move the beam back. The sync pulses sit inside that extra time. The signals are active low, so they sit at 1 normally and drop to 0 during the pulse.

The assign lines are combinational. They have no clock, so they change immediately when hc and vc changes. 
Why 656 & 752 for hsync? 640 visible + 16 sync front porch = 656 is where the pulse starts, and it lasts 96 cycles, so it ends at 752.

the pixel generator

so far, we only produced the timing. but a monitor needs color: RGB for each pixel. 
This design will output a 4 bit value per channel, which is what typical FPGA boards resistor ladder VGA port expects. 
color must be black (all 0's) when active is low. During blanking the monitor uses the signal to calibrate its black level, so any color there can shift the whole picture which is why active exists. 
A pixel generator is a combinational module. It has no clock nor memory. For each (x,y) it just answers "what color is this pixel?" The sync generator tells it where the beam is, and the pixel generator decides what to draw.
